## 4. 文档维护规范

### 4.1 文档更新流程

1. **需求变更提出**：由产品经理或项目经理提出变更需求
2. **影响分析**：分析受影响的文档和模块
3. **文档更新**：更新相关文档，标注变更日期和变更人
4. **评审确认**：由相关人员评审确认变更内容
5. **通知相关方**：通知受影响的项目成员

### 4.2 版本管理

| 版本号 | 说明 | 变更类型 |
|--------|------|---------|
| 1.0 | 初始版本 | 新增 |
| 1.1 | 小版本更新 | 功能微调、文字修正 |
| 2.0 | 大版本更新 | 功能增删、架构调整 |

## 5. 目录规范

### 5.1 目录职责

| 目录 | 职责 | 说明 |
|------|------|------|
| `templates/` | 模板文件 | 团队共享的标准模板，不随业务变更 |
| `v1.0/` | 版本文档 | 当前版本的实际需求文档 |
| `v{X.Y}/` | 历史版本 | 按版本号归档，方便追溯 |

### 5.2 版本迭代流程

1. 需求变更时，从当前版本目录复制到新版本目录（如 `v1.0/` → `v1.1/`）
2. 在新版本目录中修改文档
3. 更新 README 中的版本号和变更记录
4. 旧版本目录保留不删除，作为历史存档

## 6. 技术栈说明

本项目技术栈与传统 RuoYi 项目不同，采用全 JavaScript 技术栈：

| 层级 | 技术 | 说明 |
|------|------|------|
| 前端框架 | React 19 | SPA 单页应用 |
| 构建工具 | Vite 7 | 开发服务器 + 构建 |
| 路由 | React Router 7 (HashRouter) | 前端路由 |
| 样式 | Tailwind CSS 4 | 原子化 CSS |
| 后端框架 | Express 5 | Node.js Web 框架 |
| 数据库 | SQLite (better-sqlite3) | 嵌入式数据库 |
| 认证 | JWT + bcrypt | Token 认证 |
| 移动端 | Capacitor 8 | Android APK 打包 |
