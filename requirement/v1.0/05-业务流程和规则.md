## 1. 业务流程概览

### 1.1 核心业务流程清单

| 流程编号 | 流程名称 | 触发方式 | 涉及角色 | 主要系统模块 |
|---------|---------|---------|---------|------------|
| PROC-001 | 门店创建与配置流程 | 超管主动创建 | 超级管理员 | 门店管理、系统配置 |
| PROC-002 | 内容发布与审核流程 | 超管主动发布 | 超级管理员、市级管理员 | 公告管理、轮播管理 |
| PROC-003 | 购彩用户互动流程 | 用户到店触发 | 购彩用户、门店店长 | 互动中心、大乐透选号、刮刮乐 |
| PROC-004 | 开奖数据同步流程 | Cron定时触发 | 系统自动 | 爬虫模块、开奖数据 |
| PROC-005 | 中奖喜报发布流程 | 门店店长/超管提交 | 门店店长、超级管理员 | 喜报中心 |
| PROC-006 | 爬虫数据抓取流程 | Cron定时/手动触发 | 系统自动 | 爬虫模块 |
| PROC-007 | 用户认证流程 | 用户登录触发 | 所有管理员角色 | RBAC认证模块 |
| PROC-008 | 素材管理流程 | 超管主动管理 | 超级管理员 | 布局管理、刮刮乐素材 |
| PROC-009 | 设备监控流程 | 心跳上报触发 | 系统自动 | 设备监控模块 |
| PROC-010 | 远程控制流程 | 超管主动推送 | 超级管理员 | 远程控制模块 |

#### 流程说明

| 步骤 | 操作 | 责任人 | 系统响应 | 备注 |
|-----|------|-------|---------|-----|
| 1 | 登录后台系统 | 超级管理员 | 验证JWT Token | 需要role_super权限 |
| 2 | 进入门店管理 | 超级管理员 | 返回门店列表 | 包含在线状态信息 |
| 3 | 填写门店信息 | 超级管理员 | - | ID必须唯一 |
| 4 | 提交创建请求 | 超级管理员 | 校验参数并创建 | 自动复制默认配置 |
| 5 | 配置游戏权限 | 超级管理员/店长 | 更新门店配置 | 可设置大乐透/套餐 |
| 6 | 配置刮刮乐 | 门店店长 | 更新scratchConfig | 每档位最多60张 |
| 7 | 门店上线 | 系统自动 | 心跳检测在线状态 | 30秒超时判定离线 |

#### 参与角色

- **超级管理员**: 创建门店、分配ID密码、配置基础信息
- **省级管理员**: 查看全省门店、编辑配置
- **市级管理员**: 管理本市门店
- **门店店长**: 管理本店配置、提交喜报

#### 输入输出

**输入:**
- 门店ID (唯一标识，如 `shop-001`)
- 门店名称
- 所属城市 (福建省9个地市)
- 管理密码 (adminKey，8位以上)
- 渠道类型 (tv/android)

**输出:**
- 创建成功的门店对象
- 包含默认游戏配置
- 包含默认状态: open

**输入:**
- Cron配置 (开奖日、时间窗口、间隔)
- 官方API返回的JSON数据

**输出:**
- 更新后的data.json文件
- 结算后的票据状态 (won/lost)
- 中奖金额统计

└────────┬────────┘                    └────────┬────────┘
         │                                      │
         ▼                                      ▼
┌─────────────────────────────────────────────────────────┐
│  存储到 globalDeviceStatus[id].pendingCommand           │
│  - 设置时间戳                                            │
│  - 记录命令日志                                          │
└────────┬────────────────────────────────────────────────┘
         │
         ▼
    ┌─────────────────┐
    │  等待客户端心跳   │ ◄── 下次心跳时获取命令
    └────────┬────────┘
             │
             ▼
    ┌─────────────────┐
    │  客户端执行命令   │
    │  - refresh: 刷新页面│
    │  - 其他自定义命令  │
    └────────┬────────┘
             │
             ▼
    ┌─────────────────┐
    │  记录执行日志     │ ◄── storeLog()
    └────────┬────────┘
             │
             ▼
    ○ 结束
```

#### 流程说明

| 步骤 | 操作 | 责任人 | 系统响应 | 备注 |
|-----|------|-------|---------|-----|
| 1 | 登录后台 | 超级管理员 | 验证权限 | superKey或JWT |
| 2 | 选择控制方式 | 超级管理员 | - | 单店/全局 |
| 3 | 构造命令 | 超级管理员 | - | action+timestamp |
| 4 | 存储命令 | 系统自动 | 写入内存 | pendingCommand |
| 5 | 等待心跳 | 系统自动 | - | 最长60秒 |
| 6 | 客户端执行 | 门店设备 | 执行命令 | 刷新页面等 |
| 7 | 记录日志 | 系统自动 | 写入store_logs | 命令执行记录 |

#### 参与角色

- **超级管理员**: 推送命令、查看执行结果
- **门店设备**: 接收并执行命令

#### 输入输出

**输入:**
- 门店ID (单店控制)
- superKey (鉴权)
- 命令对象 (action, timestamp)

**输出:**
- 命令推送成功响应
- 命令执行日志

## 4. 业务规则

### 4.1 校验规则

#### 4.1.1 门店ID校验

```
规则: 门店ID必须全局唯一
校验位置: POST /api/super/create-store
校验逻辑:
  - 检查db.stores中是否已存在相同ID
  - 如重复则返回错误: "Store already exists"
格式要求:
  - 推荐格式: shop-XXX 或 自定义字符串
  - 不能为 "default" (系统保留)
```

#### 4.1.2 手机号校验

```
规则: 联系电话必须为11位数字
正则表达式: /^\d{11}$/
校验位置: POST /api/store/update
校验逻辑:
  - normalizePhone11(): 去除所有非数字字符，截取前11位
  - isValidPhone11(): 校验是否为11位数字
错误提示: "联系电话只能输入11位数字"
```

#### 4.1.3 经理称呼校验

```
规则: 经理称呼格式为 "姓氏+称呼"
正则表达式: /^[\u4e00-\u9fa5]{1,2}(店长|先生|女士)$/
校验位置: POST /api/store/update
校验逻辑:
  - isValidManagerByTemplates(): 根据模板列表校验
  - 姓氏: 1-2个汉字
  - 称呼: 从managerTitleTemplates中选择 (默认: 店长/先生/女士)
示例:
  - ✓ 张店长
  - ✓ 李先生
  - ✓ 王女士
  - ✗ 张经理 (不在模板中)
  - ✗ 张大店长 (姓氏超过2字)
错误提示: "联系人格式只能为X店长、X先生或X女士（X为姓氏）"
```

#### 4.1.4 密码校验

```
规则: 密码必须满足以下条件
校验位置: validatePassword() in auth.js
校验逻辑:
  1. 长度不能少于8位
  2. 必须包含字母 (/[a-zA-Z]/)
  3. 必须包含数字 (/[0-9]/)
错误提示:
  - "密码长度不能少于8位"
  - "密码必须包含字母"
  - "密码必须包含数字"
示例:
  - ✓ admin888
  - ✓ Test1234
  - ✗ 12345678 (无字母)
  - ✗ abcdefgh (无数字)
  - ✗ Ab1 (长度不足)
```

#### 4.1.5 喜报内容敏感词校验

```
规则: 喜报内容不能包含敏感词
敏感词列表 (默认):
  - 必中
  - 保中
  - 稳赚
  - 包赚
  - 内幕
  - 代投
  - 返利
校验位置: containsSensitiveWord()
校验逻辑:
  - 将文本转为小写
  - 遍历敏感词列表检查是否包含
  - 如命中则返回错误: "第X条喜报命中敏感词：XXX"
配置位置: db.superConfig.winnerSensitiveWords
```

#### 4.1.6 大乐透选号校验

```
规则: 大乐透选号必须符合官方规则
红球:
  - 数量: 5个
  - 范围: 01-35
  - 不能重复
蓝球:
  - 数量: 2个
  - 范围: 01-12
  - 不能重复
校验位置: 前端PrizeCalculator类
示例:

  - ✗ 红: [01, 05, 12, 23, 36] (超出范围)
  - ✗ 红: [01, 05, 05, 23, 35] (有重复)
```

### 4.2 计算规则

#### 4.2.1 彩票价格计算

```
规则: 复式投注价格计算公式
公式: 价格 = C(红球数, 5) × C(蓝球数, 2) × 2元

其中:
  - C(n, k) = n! / (k! × (n-k)!) 为组合数
  - 每注基础价格: 2元

示例:
  - 单式: 5红+2蓝 = C(5,5) × C(2,2) × 2 = 1 × 1 × 2 = 2元
  - 复式: 6红+2蓝 = C(6,5) × C(2,2) × 2 = 6 × 1 × 2 = 12元
  - 复式: 6红+3蓝 = C(6,5) × C(3,2) × 2 = 6 × 3 × 2 = 36元
  - 复式: 7红+3蓝 = C(7,5) × C(3,2) × 2 = 21 × 3 × 2 = 126元

实现位置: 前端PriceCalculator
```

#### 4.2.2 奖级匹配规则

```
规则: 9个奖级自动匹配
实现位置: PrizeCalculator.checkSingle() in index.js

匹配逻辑:
  1. 计算红球命中数 (rHit)
  2. 计算蓝球命中数 (bHit)
  3. 组合键: "${rHit}+${bHit}"
  4. 查找PRIZES表匹配奖级

奖级表:
  ┌────────┬──────────┬──────────┬─────────┐
  │ 奖级   │ 红球命中  │ 蓝球命中  │ 奖金    │
  ├────────┼──────────┼──────────┼─────────┤
  │ 一等奖 │    5     │    2     │ 浮动    │
  │ 二等奖 │    5     │    1     │ 浮动    │
  │ 三等奖 │    5     │    0     │ 10,000  │
  │ 四等奖 │    4     │    2     │ 3,000   │
  │ 五等奖 │    4     │    1     │ 300     │
  │ 六等奖 │    3     │    2     │ 200     │
  │ 七等奖 │    4     │    0     │ 100     │
  │ 八等奖 │    3     │    1     │ 15      │
  │ 八等奖 │    2     │    2     │ 15      │
  │ 九等奖 │    3     │    0     │ 5       │
  │ 九等奖 │    2     │    1     │ 5       │
  │ 九等奖 │    1     │    2     │ 5       │
  │ 九等奖 │    0     │    2     │ 5       │
  └────────┴──────────┴──────────┴─────────┘

复式投注展开:
  - 红球组合: C(红球数, 5)
  - 蓝球组合: C(蓝球数, 2)
  - 总注数 = 红球组合 × 蓝球组合
  - 逐注计算，累加总奖金
```

### 4.3 限制条件

#### 4.3.1 登录失败锁定

```
规则: 连续登录失败5次，锁定30分钟
配置:
  - LOGIN_FAIL_LIMIT = 5
  - LOGIN_LOCK_MS = 30 * 60 * 1000 (30分钟)
实现: loginFailMap (内存Map)
校验位置: checkLoginLock() / recordLoginFail() in auth.js

处理流程:
  1. 用户登录失败 → recordLoginFail(username)
  2. 失败次数+1
  3. 如次数 >= 5 → 设置lockedUntil = Date.now() + 30分钟
  4. 下次登录前 → checkLoginLock(username)
  5. 如在锁定期内 → 返回错误 "账号已锁定，请X分钟后重试"
  6. 如超过锁定期 → 清除记录，允许登录
```

#### 4.3.2 JWT有效期

```
规则: JWT Token有效期为8小时
配置: JWT_EXPIRES = '8h'
实现: signToken() in auth.js
校验位置: authMiddleware() in auth.js

处理流程:
  1. 用户登录成功 → 签发JWT
  2. JWT包含: userId, username, roleId
  3. 有效期: 8小时
  4. 过期后 → verifyToken()返回null
  5. 前端收到401 → 跳转登录页
```

#### 4.3.3 心跳超时

```
规则: 30秒无心跳判定为离线
配置: ONLINE_TIMEOUT_MS = 30000 (30秒)
实现: globalDeviceStatus (内存对象)
校验位置: 心跳处理 + 定时检测

处理流程:
  1. 门店设备每30秒发送心跳
  2. 服务器更新lastPing时间戳
  3. 定时器每30秒遍历所有设备
  4. 如 Date.now() - lastPing > 30秒 → 标记离线
  5. 记录离线日志 (包含最后性能数据)
```

#### 4.3.4 日志保留

```
规则: 默认保留30天日志
配置: logRetentionDays = 30 (可在1-365天调整)
实现: deleteOldLogs in db.js
执行: 每小时自动清理

处理流程:
  1. 每小时执行一次清理任务
  2. 计算截止时间: Date.now() - 30天
  3. 删除store_logs表中created_at < 截止时间的记录
  4. 删除admin_logs表中created_at < 截止时间的记录
  5. 记录清理结果到日志
```

#### 4.3.5 刮刮乐素材限制

```
规则: 每个档位最多选择60张素材
档位配置:
  - 10元: maxCount = 60
  - 20元: maxCount = 30
  - 30元: maxCount = 20
  - 50元: maxCount = 20
实现: SCRATCH_TIERS in index.js
校验位置: 门店配置选择素材时

处理流程:
  1. 门店店长选择素材
  2. 系统检查该档位已选数量
  3. 如超过maxCount → 返回错误
  4. 保存选择到scratchConfig.selected
```

### 4.4 关联规则

#### 4.4.1 删除门店级联删除

```
规则: 删除门店时，级联删除相关数据
删除范围:
  1. 门店记录 (stores表)
  2. 相关票据 (tickets表，按storeId过滤)
  3. 统计数据 (analytics表，按storeId删除)
  4. 门店日志 (store_logs表，按storeId删除)
实现位置: POST /api/super/delete-store

处理流程:
  1. 验证superKey权限
  2. 检查不能删除default门店
  3. 删除stores表中该门店记录
  4. 删除tickets表中storeId匹配的记录
  5. 删除analytics表中storeId匹配的记录
  6. 删除store_logs表中store_id匹配的记录
  7. 保存数据库

注意: 不删除admin_users中关联的用户，需手动处理
```

#### 4.4.2 禁用用户立即失效Token

```
规则: 禁用用户时，该用户的所有现有Token立即失效
实现位置: authMiddleware() in auth.js

处理流程:
  1. 管理员禁用用户 → status设为0
  2. 用户下次请求携带Token
  3. authMiddleware验证Token → 解码成功
  4. 查询用户表 → 发现status !== 1
  5. 返回403错误: "账号已被禁用"
  6. 前端收到403 → 跳转登录页

效果: 虽然Token未过期，但因用户状态检查而立即失效
```

  - 数据格式错误 (400)

处理方式:
  - 返回具体错误信息
  - 前端显示友好提示
  - 记录数据异常日志
```

#### 5.1.5 系统异常

```
定义: 服务器内部错误
HTTP状态码: 500
示例:
  - 数据库操作失败
  - 文件读写失败
  - 内存不足

处理方式:
  - 返回通用错误信息
  - 记录详细错误日志 (console.error)
  - 触发告警 (如配置)
```

#### 5.1.6 爬虫异常

```
定义: 数据抓取相关异常
HTTP状态码: 502 / 500
示例:
  - 数据源超时
  - 数据格式异常
  - 网络连接失败

处理方式:
  - 降级使用本地缓存数据
  - 记录爬虫错误日志
  - 下次定时任务重试
```

---

### 5.2 异常处理策略

#### 5.2.1 爬虫异常降级策略

```
策略: 降级使用本地缓存数据
实现位置: refreshSourcesAndHistory() / fetchAllDrawHistories()

处理流程:
  1. 爬虫任务执行
  2. 如发生异常 (超时/格式错误等)
  3. 捕获异常，记录错误日志
  4. 检查本地缓存 (db.sources / db.drawHistory)
  5. 如缓存存在 → 返回缓存数据 + warning标记
  6. 如缓存不存在 → 返回空数据 + error标记

前端处理:
  - 检查response中的warning字段
  - 如有warning → 显示"数据可能不是最新"提示
  - 如有error → 显示"数据获取失败"提示
```

#### 5.2.2 认证异常处理策略

```
策略: 跳转登录页
实现位置: authMiddleware() + 前端请求拦截器

处理流程:
  1. 前端发起请求，携带Authorization头
  2. 后端authMiddleware验证Token
  3. 如Token无效/过期 → 返回401
  4. 前端拦截器捕获401
  5. 清除本地Token
  6. 跳转到登录页
  7. 显示"登录已过期，请重新登录"

特殊处理:
  - 如用户被禁用 → 返回403，显示"账号已被禁用"
  - 如角色不存在 → 返回403，显示"角色不存在"
```

#### 5.2.3 数据异常处理策略

```
策略: 返回友好错误提示
实现位置: 各API路由

处理流程:
  1. API接收到请求
  2. 参数校验/业务校验
  3. 如数据不存在 → 返回404 + "XXX不存在"
  4. 如数据重复 → 返回400 + "XXX已存在"
  5. 如格式错误 → 返回400 + 具体格式要求
  6. 前端显示错误提示

错误信息规范:
  - 使用中文描述
  - 说明具体问题
  - 提供解决建议 (如可能)
```
