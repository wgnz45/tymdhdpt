## 3. 数据权限

### 3.1 数据权限类型

参照 RuoYi 框架的数据权限机制，定义以下数据权限类型：

| 数据权限 | 说明 | 适用场景 |
|---------|------|---------|
| 全部数据权限 | 可查看系统中的所有数据 | 超级管理员、系统管理员 |
| 本部门及以下数据权限 | 可查看本部门及下级部门的数据 | 部门经理 |
| 本部门数据权限 | 仅可查看本部门的数据 | 部门主管 |
| 仅本人数据权限 | 仅可查看自己的数据 | 普通员工 |

### 3.3 数据权限配置方式

**Service 层配置**：
```java
@Service
public class DemoStudentServiceImpl implements IDemoStudentService {
    
    @Autowired
    private DemoStudentMapper studentMapper;
    
    @Override
    @DataScope(deptAlias = "d", userAlias = "u")
    public List<DemoStudent> selectDemoStudentList(DemoStudent student) {
        return studentMapper.selectDemoStudentList(student);
    }
}
```

**Mapper XML 配置**：
```xml
<select id="selectDemoStudentList" parameterType="com.ruoyi.demo.domain.DemoStudent" resultMap="DemoStudentResult">
    SELECT d.*, u.user_name AS create_name
    FROM demo_student d
    LEFT JOIN sys_user u ON d.create_by = u.user_id
    LEFT JOIN sys_dept d ON d.dept_id = d.dept_id
    WHERE d.del_flag = '0'
    <!-- 数据权限过滤 -->
    ${dataScope}
</select>
```

## 5. 权限变更流程

### 5.1 权限申请流程

```
┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐
│ 申请人  │───>│ 部门经理 │───>│ 系统管理员│───>│ 权限生效 │
│ 提交申请 │    │ 审批    │    │ 配置权限 │    │         │
└─────────┘    └─────────┘    └─────────┘    └─────────┘
```

**流程说明**：
1. **申请人提交申请**：填写权限申请表，说明申请原因和所需权限
2. **部门经理审批**：审核申请的必要性和合理性
3. **系统管理员配置**：在系统中配置相应权限
4. **权限生效**：申请人刷新缓存或重新登录后权限生效

### 5.2 权限审批流程

**审批要点**：
- 申请权限是否与岗位职责匹配
- 是否存在权限冲突（如审批人与申请人不能为同一人）
- 是否符合最小权限原则

**审批结果**：
- **通过**：流转至系统管理员配置
- **驳回**：返回申请人，说明驳回原因
- **转交**：转交其他审批人

### 附录 C：常见问题

**Q1: 新增角色后菜单不显示？**
- A: 检查角色是否关联菜单，刷新缓存后重新登录

**Q2: 数据权限不生效？**
- A: 检查 Service 层是否添加@DataScope 注解，Mapper XML 是否添加${dataScope}

**Q3: 如何回收临时权限？**
- A: 在角色管理中移除相应权限，或临时禁用角色
