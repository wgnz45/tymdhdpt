## 1. 角色定义

系统预置 7 个角色（`server/db.js` `initRBAC()` 函数），首次启动时自动创建：

| 角色ID | 名称 | 级别 | 说明 |
|--------|------|------|------|
| `role_super` | 超级管理员 | super | 系统最高权限，全部功能访问 |
| `role_province` | 省级管理员 | province | 省级管理，除用户管理和系统设置外全部权限 |
| `role_city` | 市级管理员 | city | 管辖本市门店，仅限本市数据 |
| `role_store` | 门店店长 | store | 通过前端隐藏入口登录，管理本店配置 |
| `role_tech` | 技术运维 | province | 系统维护、远程控制、布局配置 |
| `role_analyst` | 数据分析员 | province | 查看数据看板和报表，只读权限 |
| `role_auditor` | 审计监察员 | province | 全模块只读访问，用于合规审计 |

**角色层级说明**：
- `super`：超级管理员，可访问所有数据和功能
- `province`：省级管理员，可访问全省数据
- `city`：市级管理员，仅可访问管辖城市数据
- `store`：门店级，仅可访问本店数据

**系统内置角色**：所有预置角色的 `is_system = 1`，不可删除，仅可编辑权限。

## 3. 权限标识符规范

### 3.1 格式

权限标识符格式：`{模块}:{操作}`

**示例**：
- `dashboard:view` — 查看仪表盘
- `store_manage:edit` — 编辑门店管理
- `user_manage:delete` — 删除用户
- `layout:view` — 查看素材管理

### 3.2 权限存储格式

角色权限以 JSON 对象存储在 `roles` 表的 `permissions` 字段中：

```json
{
  "dashboard": ["view"],
  "store_manage": ["view", "edit", "delete"],
  "store_config": ["view", "edit"],
  "remote_control": ["view", "edit"],
  "announcements": ["view", "edit", "delete"],
  "tickets": ["view", "delete"],
  "layout": ["view", "edit", "delete"],
  "scratch": ["view", "edit", "delete"],
  "draw_data": ["view", "edit"],
  "fortune": ["view", "edit"],
  "system_config": ["view", "edit"],
  "user_manage": ["view", "edit", "delete"],
  "logs": ["view", "delete"],
  "carousel": ["view", "edit", "delete"]
}
```

### 3.3 权限检查机制

**后端检查**（`server/auth.js` `requirePerm` 函数）：

```javascript
function requirePerm(module, action) {
    return (req, res, next) => {
        const perms = req.user.permissions;
        if (!perms[module] || !perms[module].includes(action)) {
            return res.status(403).json({ error: '权限不足' });
        }
        next();
    };
}
```

**前端检查**（`src/admin/AdminLayout.jsx`）：

```javascript
const adminPerms = adminUser?.permissions || {};
const hasPerm = (mod) => !!adminPerms[mod];

// 菜单根据权限动态过滤
if (hasPerm('store_manage')) storeOps.push({ icon: Globe, label: '门店管理', path: '/admin/stores' });
```

## 4. 数据权限

### 4.1 数据权限范围

| 角色级别 | 数据范围 | 说明 |
|----------|----------|------|
| super | 全部数据 | 可访问所有门店、所有城市数据 |
| province | 全省数据 | 可访问所有门店数据 |
| city | 本市数据 | 仅可访问管辖城市的门店数据 |
| store | 本店数据 | 仅可访问关联门店的数据 |

### 4.2 城市数据隔离

**支持的9个地市**（`FUJIAN_CITIES` 常量）：
- 福州、厦门、莆田、三明、泉州、漳州、南平、龙岩、宁德

**用户城市绑定**（`admin_users` 表 `city` 字段）：
- 省级角色：`city` 为空，可访问全省数据
- 市级角色：`city` 设置为具体城市名，仅可访问该城市门店
- 门店角色：`store_id` 设置为具体门店ID，仅可访问该门店数据

### 4.3 门店数据隔离

**门店店长绑定**（`admin_users` 表 `store_id` 字段）：
- 通过前端隐藏入口登录（三击Logo）
- 使用门店管理密钥（`adminKey`）认证
- 会话超时：5分钟无活动自动登出

**门店管理员登录流程**（`src/admin/AdminLayout.jsx`）：
1. 访问 `/#/s/{storeId}/admin`
2. 输入门店管理密钥
3. 验证通过后存储 `auth_{storeId}` 和 `storeKey_{storeId}` 到 sessionStorage
4. 记录最后活动时间 `lastActive_{storeId}`
5. 鼠标/键盘/触摸活动重置超时计时器

## 5. 认证机制

### 5.1 JWT Token 认证

**Token 签发**（`server/auth.js` `signToken` 函数）：

```javascript
const JWT_SECRET = process.env.JWT_SECRET || 'tymdhdpt_jwt_secret_2026_v1';
const JWT_EXPIRES = '8h';

function signToken(payload) {
    return jwt.sign(payload, JWT_SECRET, { expiresIn: JWT_EXPIRES });
}
```

**Token 载荷**：
```json
{
  "userId": "uuid",
  "username": "admin",
  "roleId": "role_super"
}
```

**Token 验证**（`authMiddleware` 中间件）：
1. 从 `Authorization: Bearer {token}` 头提取 Token
2. 验证 Token 签名和有效期
3. 查询用户是否存在且状态正常
4. 查询角色是否存在
5. 将用户信息挂载到 `req.user`

**Token 存储**（前端）：
- 存储位置：`sessionStorage`
- Key：`adminToken`
- 用户信息：`adminUser`（JSON字符串）

### 5.2 密码规范

**密码验证规则**（`server/auth.js` `validatePassword` 函数）：

```javascript
function validatePassword(pw) {
    if (!pw || pw.length < 8) return '密码长度不能少于8位';
    if (!/[a-zA-Z]/.test(pw)) return '密码必须包含字母';
    if (!/[0-9]/.test(pw)) return '密码必须包含数字';
    return null;
}
```

**密码要求**：
- 最小长度：8位
- 必须包含：字母（a-zA-Z）
- 必须包含：数字（0-9）

**密码哈希**：
- 算法：bcrypt
- Salt rounds：10
- 存储：`admin_users` 表 `password_hash` 字段

**默认超级管理员账号**：
- 用户名：`admin`
- 密码：`admin888`
- 首次启动自动创建

### 5.3 登录失败锁定

**锁定策略**（`server/auth.js`）：

```javascript
const LOGIN_FAIL_LIMIT = 5;
const LOGIN_LOCK_MS = 30 * 60 * 1000; // 30 minutes

function recordLoginFail(username) {
    const info = loginFailMap.get(username) || { count: 0, lockedUntil: null };
    info.count++;
    if (info.count >= LOGIN_FAIL_LIMIT) {
        info.lockedUntil = Date.now() + LOGIN_LOCK_MS;
        info.count = 0;
    }
    loginFailMap.set(username, info);
}
```

**规则**：
- 最大失败次数：5次
- 锁定时间：30分钟
- 锁定提示：`"账号已锁定，请X分钟后重试"`
- 存储方式：内存 Map（重启后重置）

### 5.4 门店管理密钥认证

**传统认证方式**（向后兼容）：

```javascript
function superKeyOrAuth(req, res, next) {
    // 先检查 JWT
    const authHeader = req.headers.authorization;
    if (authHeader && authHeader.startsWith('Bearer ')) {
        return authMiddleware(req, res, next);
    }
    // 回退到 superKey
    const superKey = req.body?.superKey || req.query?.superKey;
    if (superKey && superKey === db.superConfig.superKey) {
        req.user = { /* 超级管理员权限 */ };
        return next();
    }
    return res.status(401).json({ error: '未登录或密钥错误' });
}
```

**门店密钥认证**：
- 门店管理密钥：`stores` 表 `adminKey` 字段
- 认证接口：`POST /api/store/login`
- 验证方式：比对 `adminKey` 明文
- 会话管理：前端 sessionStorage

### 7.2 部门表结构

**表名**：`departments`

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | TEXT | 部门ID（主键） |

### 7.3 部门与角色的关联

部门通过 `admin_users` 表的 `dept_id` 字段与用户关联。一个角色可以包含多个部门的用户，一个部门也可以包含多个角色的用户。

**典型配置示例**：

| 部门 | 建议角色 | 说明 |
|------|----------|------|
| 综合管理部 | 超级管理员、省级管理员 | 系统管理和综合协调 |
| 市场运营部 | 省级管理员、市级管理员 | 门店运营和市场推广 |
| 技术运维部 | 技术运维 | 系统维护和技术支持 |
| 数据监控部 | 数据分析员 | 数据分析和报表 |
| 财务审计部 | 审计监察员 | 合规审计和监察 |
| 门店管理部 | 门店店长、市级管理员 | 门店日常管理 |

### 7.4 部门管理操作

**新增部门**：
- 接口：`POST /api/rbac/departments`
- 必填字段：`name`（部门名称）
- 可选字段：`level`（级别）、`city`（城市）

**编辑部门**：
- 接口：`PUT /api/rbac/departments/{id}`
- 可修改字段：`name`、`level`、`city`

**删除部门**：
- 接口：`DELETE /api/rbac/departments/{id}`
- 前置检查：部门下是否有用户（有用户时提示确认）

**查看部门用户**：
- 通过用户管理Tab筛选部门
- 部门下拉显示：部门名称 + 用户数量
